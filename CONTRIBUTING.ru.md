# Участие в разработке Step7ProjectExplorer

[English](CONTRIBUTING.md) | **Русский**

Предлагайте изменения через **pull request**. Доступ на запись в этот репозиторий не нужен: работайте в своём fork и направляйте PR в ветку `main` основного репозитория. [Cody / @Svyatogor3757](https://github.com/Svyatogor3757) проверяет предложения и решает, какие изменения сливать. Само открытие PR основной код не меняет.

## Как предложить изменение

1. Посмотрите [существующие Issues](https://github.com/Svyatogor3757/vscode-step7-project-explorer/issues) и [pull request](https://github.com/Svyatogor3757/vscode-step7-project-explorer/pulls). Для большой доработки полезно сначала обсудить объём в Issue.
2. Нажмите **Fork**, клонируйте свой репозиторий и создайте ветку:

   ```powershell
   git clone https://github.com/YOUR-USERNAME/vscode-step7-project-explorer.git
   cd vscode-step7-project-explorer
   git switch -c fix/short-description
   ```

3. Внесите правки по одной задаче. Независимые исправления лучше отправлять отдельными PR.
4. Выполните проверки, относящиеся к изменению, сделайте коммит и отправьте ветку в свой fork.
5. На GitHub выберите **Contribute → Open pull request**. Base – `Svyatogor3757/vscode-step7-project-explorer:main`, head – ветка вашего fork. Опишите проблему, решение и выполненные проверки. Для незавершённой работы используйте draft PR.

Владелец может попросить доработки. Новые коммиты в той же ветке обновляют PR; создавать отдельный запрос для каждой правки не нужно. Инструкция GitHub: [Creating a pull request from a fork](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request-from-a-fork).

## Сборка и проверки

Изменения кода разрабатываются и проверяются на **Windows** с Node.js 22 и .NET SDK, поддерживающим сборку .NET Framework 4.8 x86. В CI используется .NET SDK 10. Для компиляции самого расширения STEP 7 не нужен.

```powershell
npm ci
npm run build:backend
npm test
npm run licenses:audit
```

Переводы редактируются в `language/interface_*.json`. Выполните `npm run languages:generate` и закоммитьте созданные словари; `package.nls*.json` вручную не редактируются. Отображаемое название **Step7ProjectExplorer** сохраняется при любом языке.

Для правок только в документации проверьте ссылки и вторую языковую версию; полная локальная сборка backend не требуется. CI у PR всё равно выполняется автоматически либо после разрешения владельцем запуска для нового участника.

Изменения нативной записи требуют настоящей проверки **импорт → компиляция → экспорт** на отдельном тестовом проекте STEP 7 V5.5 SP3 / S7-300. Укажите версию среды и результат. Node-тесты и моки не подтверждают совместимость со STEP 7 или ПЛК. Нельзя проверять запись на рабочем пользовательском проекте или править нативные DBF/DBT/MDX напрямую.

## Ревью и слияние

Изменения попадают в `main` через PR. Для чужого вклада нужны одобрение владельца кода, закрытые обсуждения ревью и успешная проверка GitHub Actions **windows**. Новые коммиты сбрасывают прежнее одобрение: владелец проверяет текущую редакцию. Автоматическое слияние выключено; создание PR не даёт права записи в основной репозиторий.

Для собственных PR владельца предусмотрено исключение из обязательного ревью, поскольку автор не может одобрить свой запрос. Оно действует только при слиянии PR и не разрешает прямой push в `main`, обход отдельного правила CI, force-push или удаление ветки. Подробнее: [настройки для владельца](docs/CONTRIBUTION-MAINTENANCE.md).
