# Устройство backend и работа с STEP 7 Classic

## Чтение и идентичность

`Step7Bridge.exe` — .NET Framework 4.8 x86. Офлайн-чтение выполняет DotNetSiemensPLCToolBoxLibrary 4.4.10 (`Step7ProjectV5`). Библиотека читает нативные таблицы, но наш backend не записывает DBF/DBT/MDX. Для записи используется установленный **STEP 7 Command Interface**, а не TIA Openness. Библиотеки Siemens в VSIX не входят.

Полный путь программы состоит из станции, CPU и программы; отдельные проекты могут также содержать самостоятельные S7-программы. ID объекта включает ID программы, вид объекта и нативное имя. Отображаемые имена и номера блоков не являются глобальными ключами. Файловые имена экранируются для Windows, коллизии различаются хешем.

Кодировка нативного проекта считывается из проекта, текст в рабочем каталоге — UTF-8. При записи включён строгий encoder: неподдерживаемый символ вызывает ошибку, а не замену на `?`. Исходники читаются с совместным доступом, поскольку редакторы Siemens могут удерживать файл открытым.

Семантический хеш описывает экспортированный текст. Отдельный `revision` учитывает бинарное содержимое и метаданные блока: внешнее изменение защищённого блока нельзя скрыть неизменившимся текстовым представлением. Защищённые и системные блоки не декомпилируются с обходом защиты.

## Command Interface

Корневой COM-объект — `Simatic.Simatic`, `UnattendedServerMode = true`. Проект выбирается из `Projects` по точному `LogPath`, поэтому его необходимо один раз открыть в SIMATIC Manager. Привязка `.s7p` через file moniker на целевой системе не поддерживается.

Константы проверены по установленной type library на VM:

| Объект | ConcreteType / Type |
| --- | --- |
| S7Project | 1122305 |
| S7Program | 1327361 |
| Sources | 1122308 |
| Blocks | 1138689 |
| Source | 65 |

Исходник добавляется `Sources.Next.Add(name, 65, filename)` и компилируется `Compile()`. Для прямой правки блока создаётся временный AWL-исходник, после компиляции он удаляется. При удалении исходника скомпилированные блоки остаются самостоятельными объектами.

На проверенной установке успешный SCL `Compile()` иногда возвращает коллекцию с `Count = 0`. Поэтому один return code не считается доказательством успеха: в одноразовой stage-копии сначала удаляются объявленные целевые блоки, после компиляции требуется их появление. Символьные объявления разрешаются по Symbols. Защищённые целевые блоки не перезаписываются.

## Staging и запись

1. Проверить локальные файлы, все объекты затронутых программ и отсутствие recovery.
2. Сохранить сырую копию файлов нативного проекта для аварийного восстановления.
3. Создать новый TEMP-проект через COM; скопировать затронутые программы штатным `S7Program.Copy`.
4. Проверить полноту копирования. Иногда Copy пропускает открытый в SCL исходник: его текст восстанавливается в одноразовой копии через штатный Add. Неполная копия блоков останавливает операцию.
5. Применить изменения и скомпилировать копию; проверить исходники, ожидаемые блоки и таблицы.
6. Для `check` вернуть результат без изменения оригинала. Для `apply` повторить проверки конфликтов и неизменности локальных правок, создать постоянный backup при включённом режиме.
7. Сохранить recovery-барьер на диске, затем импортировать в оригинал и повторно экспортировать. Результат затронутых программ должен совпасть с результатом staging.

COM API не даёт транзакции на несколько объектов. Ошибка во время записи требует проверки оператором; recovery снимается явным `recover --acknowledge-native-state`. Снимок восстанавливается только в новый каталог. При выключенных постоянных backup recovery всё равно указывает на сырую TEMP-копию. Это средство восстановления, а не гарантированный откат работающего Siemens-проекта.

Локальная блокировка `.step7project-write.lock` исключает параллельные записи нашего инструмента. Редакторы Siemens её не учитывают. Не редактируйте одновременно одну программу двумя средствами.

## Symbols

Канонический текст — CSV либо ASC; ASC содержит префикс `126,` и поля 24/12/10/80 символов. В таблице сохраняются имя, адрес, тип и комментарий. Импорт в STEP 7 возвращает число строк и выполняет слияние, поэтому обычного `Import` недостаточно для удаления строк.

Backend создаёт временную S7-программу в том же проекте и кодировке, импортирует туда полную таблицу, сверяет число строк и поля. Только затем заменяет таблицу оригинальной программы штатным `Copy`, сохраняет имя и комментарий таблицы и удаляет временную программу. Пустая таблица также проверена.

CSV/ASC не представляет все дополнительные атрибуты symbols. `SymbolMetadata` читает описатели DBF и запрещает запись при непустых дополнительных/неизвестных полях или некорректной структуре. Это проверка только чтением; таблица остаётся доступной для просмотра. Неизвестные атрибуты нельзя молча потерять при полной замене.

## Мнемоника AWL

Офлайн-библиотеке явно передаётся English или German. Значение хранится в рабочем манифесте; экземпляры bridge независимы для разных каталогов. Это настройка экспорта в памяти, она не записывает языковые настройки нативного проекта. Выбранный язык должен совпадать с **Options → Customize → Language** в STEP 7. Существующие Sources не переводятся. Цикл с реальными операндами проверяется отдельно от нейтрального `NOP 0`.

## Интерактивный сеанс и диалоги

Компиляторы STEP 7 — COM-серверы с пользовательским интерфейсом. При Remote SSH процесс находится в session 0; `Invoke-Bridge.ps1` передаёт JSON через TEMP-файлы и запускает bridge скрытой временной задачей в интерактивном сеансе той же учётной записи. Вход в Windows требуется; сохранение пароля не требуется. После перезагрузки COM может запустить нужные приложения заново.

Пользовательский открытый исходник нельзя заменять: backend требует закрыть именно его документ. После компиляции закрывается только созданный запросом документ. Диалог SCL Overwrite Blocks подтверждается только под редактором с точным заголовком документа нашего запроса; числовые ошибки фиксируются как ошибки операции. Общие Siemens-процессы не завершаются. Нативная компиляция не обрывается по произвольному таймауту.
